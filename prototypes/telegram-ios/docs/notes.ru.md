# Telegram iOS — интерфейс-прототип

Веб-прототип интерфейса Telegram для iPhone. Нужен, чтобы позже показывать наши анимированные декорации аватара в настоящем окружении. Это отдельная часть репозитория `avatar-decorations`: она не входит в декорации, не импортирует их и не меняет общую сборку.

**Этап 1:** главный экран настроек профиля (Settings), светлое оформление по макету Figma.
**Этап 2:** сворачивание шапки при прокрутке и новая строка `Change Profile Decoration`.
**Этап 3:** исчезновение аватара, листиков и телефона при сворачивании, как в видео-референсе Telegram.
**Этап 4:** расположение листиков по скриншоту-референсу (`src/layout/headerLeaves.ts`): без жёсткого овала из экспорта Figma, бледнее к краям, плюс две копии существующих листиков по бокам.
**Этап 5:** экран Edit Profile (`src/screens/EditProfileScreen.ts`) и переход Settings → Edit → Settings (`src/navigation/Navigator.ts`). Цветные иконки — SVG-файлы пользователя (`src/assets/icons/edit-profile/`), без изменений; ресурсы Telegram не используются.

## Источник

- `reference/settings.figma.svg` — макет из Figma, рамка 402 × 874 pt (iPhone 16 Pro / 17 Pro). Все размеры и координаты взяты из него.
- `reference/settings.figma.png` — тот же SVG, отрисованный браузером. Чёрная полоса внизу — особенность браузера: в Figma на этом месте размытие.

## Отличия от макета (по ТЗ и по необходимости)

| Что | Почему |
|---|---|
| Нет круглой кнопки поиска справа внизу; панель вкладок растянута на всю ширину (25 pt от краёв), четыре вкладки по 88 pt | Требование ТЗ |
| Добавлен статус-бар iPhone (9:41, сеть, Wi-Fi, батарея) и Dynamic Island | В макете место пустое, а ТЗ просит статус-бар. Показывается только в режиме «рамка»; на телефоне виден настоящий системный |
| Текст — настоящий текст, а не контуры | Чтобы строки можно было менять и делать интерактивными. На iPhone/Mac используется системный SF Pro (как в Figma), на других системах — запасной шрифт Inter (буквы чуть шире) |
| Шестая карточка (ниже Chat Folders) не показана | В макете она пустая и почти целиком за краем экрана |
| Кнопки QR, поиск и Edit в фиолетовой шапке — «жидкое стекло» по скриншоту Telegram: фиолетовое полупрозрачное стекло с размытием фона, светлая лавандовая кромка ~1 pt, мягкая тень, белые иконки и надпись; Edit — капсула 55 × 44. При сворачивании шапки плавно переходят в светлое стекло из Figma | Референс пользователя (настоящий Telegram) |
| Кнопка поиска вверху (стеклянный круг 44 × 44 слева от Edit, отступ 12) | По референсу Telegram (этап 2). Иконка — глиф поиска из того же Figma-файла. В нижней панели поиска по-прежнему нет |
| Строка `Change Profile Decoration` между `Set Emoji Status` и `Change Profile Photo` | Этап 2. Иконка — присланный файл `icon-change-profile-decoration.svg` без изменений (холст 28 × 28), центр совмещён с центрами соседних иконок |
| Иконки Contacts / Calls / Chats — растровые PNG @2x | Так они сохранены в самом Figma-файле; взяты без изменений |

Эффекты «plus darker» из Figma (узор из листьев, тёмные иконки на стеклянных кнопках, подсветка выбранной вкладки) поддерживает только Safari. Остальные браузеры получают готовый итоговый цвет, рассчитанный по той же формуле, поэтому картинка одинакова везде.

## Команды

Нужен Node.js 20+. Команды выполняются в папке `prototypes/telegram-ios/`.

```bash
npm install                  # esbuild, TypeScript, Playwright (только для разработки)
npx playwright install chromium   # один раз, для тестов и скриншотов
npm run dev                  # прототип: http://localhost:5180 (пересобирается при изменениях)
npm run build                # dist/index.html и dist/telegram-ios-settings.html (всё в одном файле)
npm test                     # сборка + проверка раскладки
npm run typecheck            # проверка типов
npm run screenshot           # .screenshots/settings@3x.png
```

`dist/index.html` и `dist/telegram-ios-settings.html` открываются и без сервера, двойным щелчком.

## Режимы показа

- **Рамка** (компьютер): экран ровно 402 × 874 pt, безопасные зоны как в Figma (сверху 62, снизу 34). В маленьком окне весь телефон пропорционально уменьшается.
- **Устройство** (телефон): экран на весь дисплей, отступы берутся из настоящих безопасных зон iPhone.

Режим выбирается автоматически. Его можно задать вручную: `?mode=frame` или `?mode=device`.

## Сворачивание шапки (этап 2)

Шапка закреплена поверх прокручиваемого списка, а её вид зависит только от того, насколько прокручен список (`ProfileHeader.ts`, `COLLAPSE`):

- фиолетовая область уменьшается вместе с прокруткой: 268 → 112 pt, карточки всегда остаются на 16 pt ниже неё;
- имя первые 141 pt едет вместе с содержимым и плавно уменьшается с 28 до 17 pt, затем остаётся заголовком по центру между кнопками; звезда за это время исчезает;
- на отрезке 96–156 pt фиолетовый цвет переходит в светлую размытую панель, имя и статус-бар — из белого в чёрный;
- исчезновение элементов (этап 3, по видео-референсу):
  - листики (0–85 pt) стягиваются к аватару, уменьшаются и гаснут;
  - аватар (0–130 pt) поднимается к Dynamic Island и уменьшается, с 35 pt размывается, с 45 pt темнеет до чёрного, его свечение гаснет первым; с 70 pt появляется жидкая перемычка к острову (SVG-фильтр «goo»), на 112,5 pt аватар оказывается внутри острова и поглощается. На телефоне, где острова в прототипе нет, аватар вместо этого плавно гаснет;
  - телефон (10–125 pt) едет вместе с именем и бледнеет постепенно, исчезая последним;
  - ничего не скрывается через `display: none`, всё зависит только от положения прокрутки;
- QR, Search и Edit всё время на месте и нажимаются; прокрутка пальцем или колесом мыши над шапкой работает;
- при прокрутке назад всё проигрывается в обратном порядке.

Пока список короткий, внизу добавлен запас прокрутки (`.screen__content`, минимум высота экрана + 156 pt), чтобы шапка всегда сворачивалась полностью.

## Аватар и будущие декорации

`Avatar()` возвращает `{ element, photo, decorationLayer, size }`. `decorationLayer` — пустой прозрачный слой над фото, центрированный по нему и не перехватывающий нажатия. Размер слоя задаётся CSS-переменной `--avatar-decoration-size` (по умолчанию 104 pt), содержимое за его пределами не обрезается. На этом этапе декорации не подключены.

## Edit Profile (этап 5)

- Открывается кнопкой Edit; × и ✓ возвращают на Settings (✓ пока ничего не сохраняет). Переход: новый экран проявляется и поднимается на 12 pt за 0,35 с; Settings остаётся под ним с прежней прокруткой.
- Размеры и расстояния сняты со скриншотов-референсов (393 × 852) и перенесены в рамку 402 × 874 так, что × и ✓ стоят там же, где QR и Edit на Settings.
- Поля имени, фамилии и Bio — настоящие поля ввода; Bio растёт вместе с текстом.
- Строки, карточки, стеклянная кнопка и шрифты — те же компоненты, что на Settings. Отличия по референсу: тонкие разделители (1 px экрана) от x 76, значения справа на 35 pt от края карточки.
- Основная карточка: Number (+888 888 888), Username (без значения, только стрелка), Your Color, Channel («Capybara Channel»). Строки Chat Automation и её подписи нет; после карточки сразу Add Another Account (отступ 24).
- Цвета квадратов сняты со скриншота. Символы — присланные SVG пользователя (`cake.svg`, `Icon.svg`, `username.svg`, `colors.svg`, `channel.svg`), файлы не изменены: при показе они обрезаются по рисунку (viewBox), равномерно масштабируются до размера символа в Telegram (×0,82–0,92), центрируются в квадрате и окрашиваются в белый.

## Your Color (этап 6)

- Открывается строкой Your Color на Edit Profile и сразу со Settings строкой Change Profile Decoration; круглая кнопка ‹ возвращает туда, откуда пришли (экраны под верхним не пересоздаются, Edit Profile сохраняет прокрутку). Пути: Settings → Edit → Your Color → ‹ → Edit Profile → × → Settings; Settings → Change Profile Decoration → Your Color → ‹ → Settings. Одновременно открыт только один экран Your Color.
- Сверху: ‹ и переключатель Profile | Name (реализовано только состояние Profile).
- Карточка: фиолетовый предпросмотр (аватар — тот же компонент, что на Settings; Capybara ★; online), палитра, строка Add Icons To Profile; под ней подпись с синим Change ›; отдельная карточка Reset Profile Color. Секции USE A GIFT нет.
- Палитра — присланный `src/assets/your-color/Icons_Container.svg` без изменений (334 × 74, по центру). Поверх каждого круга — прозрачная кнопка; цвета читаются из файла. По умолчанию выбран фиолетовый, пятый в первом ряду; выбранный круг получает белое кольцо внутри (как на референсе).
- Цвет предпросмотра и текста online выводится из цвета образца по правилу, снятому с референса (фиолетовый #A16CDE → фон #8E6CC2, online #C19BF8; см. `src/color/profileColor.ts`). Двухцветные образцы дают двухцветный (сверху вниз) фон.
- Выбранный цвет — состояние приложения (`src/state/profileColor.ts`, `localStorage` `tg-prototype:profile-color`): сохраняется при переходах и после обновления страницы. По умолчанию — синий (первый кружок первого ряда), фон карточки #5B8EBB снят с синего референса. Reset Profile Color возвращает синий. Этот же цвет красит шапку Settings (синий #5B8EBB, кромка стеклянных кнопок #A4D8FB/#94C5EF/#70A2CB — с синего референса; фиолетовый — прежние #9C68CE и лавандовая кромка) и два кружка строки Your Color на Edit Profile (`src/color/profileTheme.ts`); меняется сразу при выборе цвета. Кнопка Apply Style — #008BFF.
- На фиолетовой карточке — те же фоновые листики, что в шапке Settings: один общий компонент `src/components/LeafPattern.ts` (тот же SVG, 16 листиков + 2 копии, те же размеры, повороты и бледность). Узор поставлен так, что его точка аватара совпадает с центром аватара карточки, поэтому композиция вокруг аватара и имени такая же; листики лежат позади аватара, имени и украшений.
- В строке Add Icons To Profile перед стрелкой — кленовый листик: присланный `src/assets/your-color/Maple.svg` без изменений, 24 pt, по центру строки, окрашен стилями в синий #008BFF.

## Примерка декораций (этап 7)

На экране Your Color вокруг аватара — бесконечная карусель: слева предыдущий вариант, на аватаре выбранный, справа следующий (референс пользователя: кадры 1–4).

### Каталог (`src/decor/catalog.ts`)

Шесть равноправных позиций, по порядку (свайп влево = следующая): **None → Paper Plane Orbit 1.0.0 → Cat Ears 1.1.0 → Christmas Lights 1.0.0 → Ghost Orbit 1.0.0 → Halloween Pumpkin 1.0.0 → None…** Экран открывается на применённом украшении (без него — на None: слева Halloween Pumpkin, справа Paper Plane Orbit). Christmas Lights — тег `christmas-lights-v1.0.0` (коммит `d4ceed3`), `releases/christmas-lights/1.0.0/dist/index.js`; гирлянда висит над верхом фото так, как её расставляет сам релиз. Cat Ears — **1.1.0** (коммит `7774aab`, тег `cat-ears-v1.1.0`, `releases/cat-ears/1.1.0/dist/index.js`): шевеление кончиков и покачивание ушек; пушок при наклоне выходит за холст (−7…514), поэтому границы взяты по пикселям. 1.0.0 в прототипе больше не подключается (в библиотеке остаётся без изменений). Paper Plane Orbit подключён из тега `paper-plane-orbit-v1.0.0` (коммит `fcfdac6`), `releases/paper-plane-orbit/1.0.0/dist/index.js`.

Каждая позиция описана только данными:

| Поле | Что это |
|---|---|
| `id`, `name` | уникальный id и название |
| `kind` | `'none'` — без декорации; `'svg'` — компонент |
| `version` | версия утверждённого релиза |
| `canvas`, `avatarArea` | холст (512) и круг фото на нём (центр 256, 256; r 218): по нему декорация совмещается с фото |
| `ink` | видимые границы всей анимации (180 кадров): должны вмещать каждый отрисованный пиксель и не выходить за контур рисунка. У Paper Plane Orbit и Christmas Lights берутся пиксели (у самолётика контур SVG учитывает и невидимые ракурсы, у гирлянды свечение лампочек выходит за контур и за холст) |
| `previewFill` | необязательно: какую долю бокового слота занимать (по умолчанию 1 — весь слот; у None — 0,5, маленький кружок) |
| `avatarScale`, `avatarOffset` | необязательная поправка масштаба и смещения на аватаре |
| `mount` | функция подключения релиза (`mountGhostOrbit`, `mountHalloweenPumpkin`, `mountCatEars`) |

None ничего не рисует — ни по бокам, ни на аватаре: на его месте виден только фон карточки.

### Карусель (`src/components/DecorationCarousel.ts`)

- **Два размера задаёт карусель, а не компоненты.** Боковой слот `previewSlotSize` — один на все декорации, сейчас **78 pt** (было 100; константа `PREVIEW_SLOT_SIZE` в `YourColorScreen.ts`). Вся анимация каждой декорации (её `ink`) вписывается в этот квадрат по большей стороне, с сохранением пропорций, по центру. Центральный слот — само фото аватара: круг фото декорации (`avatarArea`) совмещается с фото 104 pt (декорация 122,13 pt), как раньше. Между ними масштаб и положение меняются плавно.

- **Одно число — положение ленты** (`pos`, во время движения дробное). Элемент с номером k (элемент каталога `k mod n`) стоит на месте `u = k − pos`: −1 — слева, 0 — на аватаре, +1 — справа, ±2 — за краями карточки. Положение и масштаб линейно переходят между этими опорными местами, поэтому всё движется непрерывно вслед за пальцем: текущая уменьшается и уходит влево, следующая едет справа к аватару и увеличивается, справа въезжает новая, левая уходит за край. Свайп вправо — зеркально.
- Выбранная — элемент на ближайшем целом месте. Предыдущая и следующая вычисляются по кругу автоматически; правил «после X идёт Y» нет — алгоритм не зависит от числа элементов (тест с 6 заглушками).
- Жест меньше 40 % пути (и без быстрого рывка) плавно возвращает всё на место. Быстрые повторные свайпы подхватывают ленту там, где она сейчас, — без скачков и пропусков. Тап по боковому предпросмотру тоже выбирает его.
- **Экземпляры:** по одному на каждое видимое место; создаётся, когда место становится видимым, и удаляется, как только уходит. В покое — 3 места (слева, аватар, справа), в движении — не больше 4. При закрытии экрана удаляются все.
- **Без наложений:** при таком линейном движении зазор между соседями в любой момент не меньше, чем в покое; тест проверяет покадрово все пары в обе стороны.
- **Узкие iPhone:** боковые места начинаются в 63 pt от центра аватара и, если не помещаются до края карточки (отступ 6 pt), обе уменьшаются одинаково. Проверено на 320, 375, 390 и 402 pt.
- **Управление:** палец или мышь по фиолетовой карточке, тап по боковому предпросмотру, жест трекпада, клавиши ← (следующая) и → (предыдущая).

### Apply Style — сохранение украшения (`src/state/profileStyle.ts`)

- Два состояния: **предпросмотр** — то, что сейчас в центре карусели (живёт только в карусели), и **применённое** — то, что подтверждено кнопкой Apply Style.
- Свайп меняет только предпросмотр. Кнопка Apply Style («таблетка» #008BFF внизу экрана Your Color, как в Telegram) видна, только пока украшение в центре карусели отличается от сохранённого (сравниваются id, не позиции; цвет палитры на неё не влияет): мягко появляется и исчезает (прозрачность + сдвиг на 14 pt). Нажатие сохраняет id украшения из каталога (`ghost-orbit`, …, `none`) и сразу возвращает на Settings (`Navigator.popToRoot`, даже если Your Color открыт через Edit Profile). «Назад» ничего не сохраняет.
- Применённый id хранится в общем состоянии и в `localStorage` (`tg-prototype:applied-decoration`), восстанавливается при запуске. Неизвестный id или недоступное хранилище — старт без украшения, прототип не ломается.
- Settings (`src/decor/AppliedDecoration.ts`) показывает применённое украшение над аватаром: тот же компонент из каталога, тот же масштаб и положение, поверх листиков, без обрезки. `none` — ничего не монтируется. Пока Settings закрыт другим экраном, анимация на нём на паузе.
- Your Color открывается на применённом украшении.
- Проверки: `tests/apply-style.test.mjs` (весь сценарий, включая перезагрузку).

### Блёстки при переключении (`src/components/SparkleEffect.ts`)

- Когда карусель остановилась на новом украшении, вокруг аватара коротко вспыхивают 6 маленьких белых звёздочек — присланный `src/assets/your-color/star.svg` без изменений, 5,5–8 pt, некоторые бледнее, с мягким свечением. Загораются по очереди (старты 0 / 180 / 420 / 650 / 840 / 1050 мс, ±30 мс каждый раз), анимации перекрываются, но все разом не вспыхивают. Каждая: проявляется и растёт ~320 мс, сияет ~280 мс с лёгкой пульсацией, уменьшается и гаснет ~520 мс; вся последовательность ≈ 2,2 с.
- Отдельный слой прототипа поверх украшений (`pointer-events: none`), в SVG украшений ничего не добавляется — работает с любым будущим украшением.
- Запуск — один раз на завершённое переключение (событие карусели), по типу выбранного элемента: для None не запускается и гасит текущие блёстки. Промежуточные элементы при быстром листании блёсток не получают; новый запуск заменяет текущий. Незавершённый свайп и Apply Style эффект не запускают. На Settings блёсток нет. При `prefers-reduced-motion` вспышек нет.
- Проверки: `tests/sparkle.test.mjs`.

### Как добавить новую декорацию

1. Утвердить и выпустить релиз как обычно: `releases/<id>/<версия>/dist/index.js` с функцией `mount…`, константами `AVATAR_AREA`, `CANVAS_SIZE`, `LOOP_DURATION_MS` и `…_META`.
2. В `src/decor/catalog.ts` импортировать их из этой сборки и добавить в `DECORATIONS` одну запись (в нужное место по порядку).
3. Указать `ink` — видимые границы анимации. Их печатает тест «measured visible extents…» (`npm test`): если значение неверное, тест покажет измеренное.
4. При необходимости — `avatarScale`, `avatarOffset` (совмещение с фото) и `previewFill`. Размер бокового предпросмотра настраивать не нужно: декорация сама впишется в общий слот.
5. Добавить путь релиза в список разрешённых импортов в `tests/settings-screen.test.mjs`.

Код карусели менять не нужно.
